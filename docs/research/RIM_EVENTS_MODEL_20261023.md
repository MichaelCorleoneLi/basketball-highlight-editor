# 自动篮筐 + 进球判断模型（2026-10-23）

标准分析模式改用新流程：不需要手动框检测区域和篮网，Engine 自己找篮筐、找出每次“球到篮筐”，再用一个小模型判断进没进。

## 流程（`scripts/rim_scan.py`）

```text
1. 篮筐跟踪：每秒取一帧全画面，YOLO（bball_model.pt，imgsz 1280）找篮筐
2. 篮筐特写：以篮筐为中心裁 512×512，30fps 逐帧跑 YOLO 找球和篮筐框，同时记录篮网区域的像素变化
3. 篮筐事件：球进入篮筐附近（1.5 秒内多次算一次），为每次计算特征
4. 进球概率：逻辑回归（src/basketball_highlight/make_model.json），≥ 0.35 进入审核列表
5. 5 秒内的候选合并为一个片段（与旧版相同）
```

主要特征（`src/basketball_highlight/rim_events.py`）：

- 篮筐框变形：YOLO 的篮筐框包含篮网，球落进网时网被撑开，框变高、下移；擦框或从篮筐前面掉下时几乎不变。这是最强的信号；
- 篮网区像素变化：相对前一秒的上升幅度；
- 球的轨迹：进入时的位置和速度、是否在篮网通道里出现、是否从篮下出来、是否弹回篮筐上方、横向偏离；
- 静止的“球”（灯、标志）会被识别成球，出现超过全片 3% 的位置直接去掉。

## 效果（9 个视频，2026-10-21 _0015_ 到 _0023_，共 1.6 小时）

标签来自 Jack 的审核：保留的（含未标人名）= 进球，“我-没进”和排除的 = 没进；与进球片段重叠的排除项视为重复，不参与训练。每次留出一个视频测试（交叉验证）：

| | 旧版（精扫 + 兜底） | 新版 |
|---|---:|---:|
| 需要审核的片段 | 395 | 172 |
| 片段覆盖的已标进球 | 156（按定义） | 148（95%） |
| 旧版漏掉、新版找到的进球 | — | 约 10 个（逐个看过画面，大多确实是进球） |

阈值 0.35 时，事件级别找回 146/156 个进球，误判 20 个。误判里有一部分其实是开场、收尾随手投进的球（Jack 没算），所以真实误判比这个数少。

已知漏判：镜头被挡住时（有人站在镜头前、手碰到镜头）看不到篮筐，无法判断。

## 重新训练

带标签的事件存在本机 `data/labels/rim_events_20261021.json`（不进仓库，含球员名字）：

```bash
.venv/bin/python scripts/train_make_model.py data/labels/rim_events_20261021.json          # 只看交叉验证
.venv/bin/python scripts/train_make_model.py data/labels/rim_events_20261021.json --write  # 覆盖 make_model.json
```

## 进球人识别（试验，未接入）

从篮筐往回追球找到出手的人，再用 OSNet ReID（监控分析项目的模型）和其他视频里已标注的同一人比对：

- 能追到出手人：100/156；
- 外观比对（留一个视频）：整体 42/84 正确；比对有把握（第一名比第二名高 0.05 以上）时 19/20 正确，但只占约四分之一。

镜头离人远，人只有 100–150 像素高，追球也经常在篮筐附近就断了，所以现在还不够自动标名字。下一步：改进追球（更高分辨率检测远处的球）、同一场内聚类，让每个人只需要点一次名字。
