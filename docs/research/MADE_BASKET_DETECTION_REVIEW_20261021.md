# 进球检测改进评估（2026-10-21）

评估两个想法：(1) 审核结果回流、用误检样本调检测；(2) 用本机 Ollama 的视觉模型做二次判断、用人物识别推荐进球人。结论先行：**先做 (1) 的数据留存，(2) 中的 VL 复核目前不值得接入，人物识别排第三。**

## 现状：检测怎么工作

```text
代理视频 5fps → YOLO（bball_model.pt，ball/hoop）粗扫 ROI
  → generate_candidates：篮筐取检测中位数，找“球从筐上到筐下”的穿越
  → refine_dynamic_candidates：原视频 10fps 精扫 ±2.5s，轨迹 + 篮网像素变化
  → verdict：made / ambiguous / missed（missed 直接丢弃）
  → 精扫没确认的粗扫穿越也保留，标为 coarse（“高召回兜底”，service.py:1390）
```

## 已有的审核数据（12 个项目，本机 `~/Movies/BasketballProjects`）

审核页已经能“排除”片段，排除的就是误检；保留下来、打了球员标签的就是进球。所以想法 (1) 的标注**其实已经在产生**，只是没被用起来。统计结果：

| 候选来源 / 判定 | 保留（进球） | 排除（误检） | 精确率 |
|---|---:|---:|---:|
| 粗扫兜底 coarse | 23 | 249 | 8% |
| 精扫 ambiguous | 108 | 119 | 48% |
| 精扫 made | 8 | 16 | 33% |
| 合计 | 139 | 384 | 27% |

结论：

- **误检的大头是粗扫兜底**：占全部误检的 65%，十个里只有不到一个是进球。
- **现有判定几乎没有区分力**：`made` 比 `ambiguous` 还差；分数均值保留 0.74、排除 0.73；“篮网有动”（net_support）为真时 21:14，为假时 95:121。
- **召回率未知**：被判 `missed` 的候选直接丢弃，手动补的候选数为 0，所以不知道漏了多少球。

## 想法 1：审核回流

已经有的：`candidate_reviews` 存状态、球员、reason、note、审核用时；`evidence_json` 存分数、篮筐框、轨迹、各项信号；`scripts/export_review_dataset.py` 能按项目导出。

缺的（按重要性）：

1. **画面**。12 个项目里 11 个原视频已经删掉或移走，误检片段的画面再也拿不回来，只剩数值证据。需要在分析完成时为每个候选存一小段篮筐附近的裁剪（约 2 秒、320px，几十 KB），放在项目 `artifacts/` 下。这一步在后台做，不进 Engine 请求路径。
2. **漏检**。审核页加“补一个进球”的入口已存在（`create_manual_candidate`），需要确认 UI 上好用，并且导出时能区分“手动补的”，这样才能算召回率。
3. **误检原因**（可选）：排除时一键选“没投 / 打框没进 / 传球 / 其他”。`reason` 字段已有，UI 没用上。
4. **跨项目汇总导出**：一条命令把所有项目合成一个数据集，供分析和回归测试。

有了这些，就可以：先直接做一个“粗扫兜底默认隐藏或排到后面”的实验（基于上表，几乎肯定减少大量误检，代价是要看会丢几个真进球）；再用 500+ 条标签重训 `classifier.py` 里已有的逻辑回归，替换手调的门槛。

## 想法 2：本机 Ollama

- 位置：**这台 Mac**（M4 Max，36GB），`127.0.0.1:11434`，模型 `qwen3-vl:8b`（Q4，常驻约 10GB）和 `qwen3:8b`。
- “人物识别模型”不在 Ollama 里，是 `监控分析` 项目的 OSNet-AIN ReID（`identity.py`，PyTorch/MPS）。

**VL 复核试跑**：只有 `1330.MP4` 原视频还在，取了它的 3 个已审核候选（2 进 1 误），把事件前后 1.6 秒内 8 帧篮筐附近裁剪拼成一张图问 qwen3-vl。

- 速度：抽帧约 0.8 秒，模型热启动后约 0.5–1 秒/候选（让它逐帧推理时 6–24 秒）。一场 50–100 个候选，几分钟。
- 结果：两个明显进球都判成“没进”。让它逐帧说球的位置时，它对进球和误检给出几乎相同的描述，还出现重复输出直到截断。样本只有 3 个，不能下定论，但 8B 模型对“球在不在篮圈里”这种细小目标的判断看起来不可靠。
- 建议：等想法 1 存下裁剪画面、有几百条标签后，再拿同一批数据测它，用数字决定。不要现在接进流程。

**ReID 推荐进球人**：可行但更难。要先找到出手时刻（穿越前 1–2 秒）的持球人，再和已打标签片段里的人比对。好处是同一拨人反复出现，已有的球员标签可以直接当底库。无人机俯拍时人很小，ReID 效果要实测。

## 成本与约束

- 所有新步骤都必须在分析任务后台或单独的批处理里跑，不能放在 Engine 的请求处理路径上（NAS 上 12GB 视频，任何同步读取都会卡住界面）。
- 裁剪画面在分析时顺手产生，此时视频已经在读，额外成本主要是编码小片段。

## 建议顺序

1. 数据留存：每个候选存篮筐裁剪；补漏检入口；跨项目导出（同时给出当前精确率/召回率基线）。
2. 用已有标签做两件便宜的事：粗扫兜底降级实验；重训分类器替换手调门槛。
3. 用第 1 步的数据测 qwen3-vl 复核，提升明显才接入（后台、可关闭）。
4. ReID 推荐进球人。
